# プロジェクト校正ガイド

Runtime を入れた後、Work Item で校正します。Agent が質問し、プロジェクト担当者が確認します。
Unknown は根拠が届くまでブロッキングのままです。

## 確認する質問

1. このリポジトリの役割は何ですか？
2. 実際に使う言語とスタックは何ですか？
3. 本番ソースとテストはどこですか？
4. 生成物またはベンダー提供のファイルは何ですか？
5. 重要または高リスクのパスは何ですか？
6. 権威あるローカル／ホスト型品質コマンドは何ですか？
7. 変更と Release をレビューするのは誰ですか？
8. 残るリスク、例外、Unknown は何ですか？
9. ブロッキング制御を導入できる準備はありますか？
10. 更新や大きな変更の後、何を再確認しますか？

Work Item は回答をレビューできる提案にしますが、方針を自動有効化せず、担当者を証明せず、
人の承認を置き換えません。プラットフォーム例は [iOS](examples/ios.ja.md)、
[Android](examples/android.ja.md)、[Java](examples/java.ja.md) を見てください。
内部の保存方式は[校正内部モデル](../reference/calibration-session-model.ja.md)にあります。
