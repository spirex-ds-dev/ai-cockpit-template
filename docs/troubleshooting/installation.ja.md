# インストールのトラブルシューティング

不明な点があれば停止します。導入を成功に見せるために弱い回避策を使ってはいけません。

## 作業ツリーが clean ではない

既存変更を先に保存または説明し、インストールで上書きしません。

## 初期 commit またはデフォルトブランチがない

リポジトリ担当者にプロジェクト基線を作ってもらってから導入します。

## Python、Make、または必要なツールがない

承認済みのツールチェーンを導入または依頼し、準備確認をもう一度行います。

## Release 検証が失敗する

古い Release を黙って選びません。[厳格な検証経路](../getting-started/installation-security.ja.md)を使います。

## Active Work Item がある、ファイルが競合する、Cockpit Status が古い、または PR を作れない

根拠を保持し、不足する事実と担当者を記録して、該当 Work Item を開始または再開します。ライフサイクルを迂回しません。

## Hosted CI が実行されない

正確な commit と失敗 Job を記録し、リポジトリまたは CI 担当者に相談します。

## AI Cockpit をアンインストールする

独立した[アンインストール手順](uninstall.ja.md)を使ってください。最初に事実を集め、
レビューできる削除計画を作ります。プロジェクト作業を黙って削除しません。
