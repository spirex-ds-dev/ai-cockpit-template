# P0 文書の読者理解度検証プロトコル

これは調査手順であり、理解度の結果ではありません。英語・簡体字中国語・日本語の P0 経路を改訂した後、独立した読者に検証を依頼するための引き継ぎ資料です。

## 参加条件とプライバシー

- AI Cockpit の担当者ではなく、選択した言語を読める人を対象にします。
- ソフトウェア開発の経験がない読者を優先し、匿名の参加者 ID だけを記録します。
- 氏名、連絡先、勤務先、正確な場所などの識別情報は収集しません。
- 参加は任意であり、回答は集計した文書証拠だけに使うと説明します。

## 固定した読解経路

1. 選択した言語の root README と文書入口だけを渡します。
2. 目的、思想、アーキテクチャ、能力と境界、判断状態、最初の Calibration、最初の Work Item、回復の順に読んでもらいます。
3. 読解中に用語を説明したり、訂正したり、別言語を案内したりしません。
4. 質問の前に正確な文書版と使用言語を記録します。

## 六つの質問

1. このプロジェクトが解決する問題を自分の言葉で説明してください。
2. North Star は何で、実際の作業では何を意味しますか。
3. AI Cockpit が管理するものと、人または外部ツールが担うものは何ですか。
4. いつ進行し、調査し、停止しますか。
5. 導入して最初の Work Item を始めるとき、最初に何をしますか。
6. 必須の check や証拠が足りないとき、何をしますか。何をしてはいけませんか。

## 重要な境界

回答は `correct`、`partially_correct`、`incorrect`、`no_answer` のいずれかで採点し、根拠となる発言または要約を残します。[回答 schema](comprehension-validation-response.schema.json) を使ってください。静的テスト、Agent の自己評価、リンク検査、ページ数の比較は読者証拠ではありません。必要な原回答を受け取り、レビューするまで状態は `comprehension_unverified` のままです。
