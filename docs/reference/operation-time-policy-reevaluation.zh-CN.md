# 操作时策略重评估

输入阶段的审查不等于后续操作的授权。每次列出的高风险调用之前，本地模型都会重新评估：

```text
输入信任 + 请求的操作 + 实际工具调用 + 目标资源
+ 当前授权 + 证据时效 + 破坏性影响
= 执行决策
```

`OperationTimeRequest` 绑定请求、实际调用、目标、声明范围、原审批绑定、当前授权、证据时效和破坏性影响。`evaluate_operation_time_policy` 只返回 `allow`、`confirm` 或 `block`，不会执行命令或授予 Provider 权限。

模型覆盖删除、测试和 CI 修改、Branch Protection 修改、Secret 写入、推送、合并、发布、迁移、脚本执行、外部 API 写入、安装/升级和治理组件卸载。实际调用必须等于请求操作；目标或范围变化会使旧审批失效；证据过期或缺少当前授权会进入人工确认；影响未分类或请求/调用不一致会停止并给出恢复条件。

例如，创建脚本不授权之后执行该脚本；之后的 `execute_script` 会被独立重评估，不能复用 `create_script` 的审批。

## 限制

这是确定性的本地策略证据。它不认证人员、不验证 Provider 事件、不配置 Branch Protection、不执行脚本，也不进行任何外部写入。调用方仍须保留决策并执行适用的 Provider 与仓库控制。
