# Work Item status interface

`scripts/ai_generate_work_item_status.py` publishes a JSON status for every
active Contract/Summary pair under `.ai/cockpit/work-items/`, plus
`.ai/cockpit/work-items/index.json`. It is a read-only projection for an
external Agent or orchestrator; it does not schedule, prioritize, retry, or
execute Work Items.

Generate the index from the current worktree:

```bash
python scripts/ai_generate_work_item_status.py
```

Generate one item explicitly:

```bash
python scripts/ai_generate_work_item_status.py \
  --contract .ai/work-items/active/example.contract.json \
  --summary .ai/work-items/active/example.summary.json
```

Each record includes `workItem`, `state` (`green`, `yellow`, `red`, or
`unknown`), lifecycle `phase`, `blocking`, `blockers`,
`humanDecisionRequired`, bounded `safeActions`, `baseCommit`, `branch`,
`lastVerificationAt`, `evidenceFreshness`, source digests, and `updatedAt`.
The record is validated by
[work-item-status-interface.schema.json](../../.ai/schemas/work-item-status-interface.schema.json).

The projection is fail-closed. Missing or malformed source files, missing
required verification, commit-mismatched verification, invalid timestamps, or
evidence bound to another Work Item produce `unknown` or another non-green
state with explicit diagnostics. A status must never become green by inferring
from another Work Item or from Agent self-report. No progress percentage is
published.

The existing human-facing `.ai/cockpit/current_status.md` remains generated by
`scripts/ai_generate_status.py` and is not replaced or modified by this
interface. The status interface is repository-local; cross-worktree aggregation
and scheduling remain the responsibility of the external Agent.
